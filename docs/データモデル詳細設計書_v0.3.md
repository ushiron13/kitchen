## 0. 設計方針

| # | 方針 | 理由 |
|---|------|-----|
| 1 | すべてのテーブルに `created_at` / `updated_at` を持たせる | 監査・デバッグ容易性 |
| 2 | ENUM はTEXT + CHECK制約で表現 | SQLiteはENUM未対応 |
| 3 | 半構造データはJSONカラム（JSON1拡張） | 嗜好・LLMメタ等 |
| 4 | **レシピはソフト削除（is_archived）、それ以外はハード削除+トランザクション履歴で追跡** | DM-06 + MVPシンプル優先 |
| 5 | 日付/日時はISO 8601テキスト、格納はUTC、表示時にJST変換 | 詳細は第8章 |
| 6 | 真偽値は INTEGER (0/1) | SQLite慣習 |
| 7 | PRAGMA foreign_keys = ON | 参照整合性 |
| 8 | PRAGMA journal_mode = WAL | 並行読み書き性能 |
| 9 | `updated_at` 自動更新はトリガーで実装 | SQLiteは `ON UPDATE` 構文未対応 |
| 10 | 在庫数量は `stock_transaction` 経由でのみ更新（直接UPDATE禁止） | R-01 整合性確保 |
| 11 | 未知食材は `recipe_ingredient.raw_name` に保持、後続ジョブで `food_id` を解決 | R-02 LLM主導運用への対応 |
| 12 | 食材名の表記揺れは `food_alias` テーブル + Haiku正規化で吸収 | R-03 再利用精度向上 |
| **13** | **レシピ instructions は Markdown 形式** | **DM-02、編集容易性とレンダリングのバランス** |
| **14** | **MVPでは栄養情報は保持しない（Phase 2で再導入）** | **DM-03、スコープ最小化** |
| **15** | **meal_plan の status は手動更新、ただし補助関数で「全完了判定」「全完了化」を提供** | **DM-07、中途半端な自動判定を避ける** |

### 4.2 食材指定レシピ検索（v0.3 更新: is_archived 除外）

```sql
WITH resolved_ingredients AS (
    SELECT id AS food_id FROM food_master WHERE name IN (?, ?, ?)
    UNION
    SELECT food_id FROM food_alias WHERE alias IN (?, ?, ?)
)
SELECT
    r.id, r.name, r.cook_time_min, r.is_favorite, r.reuse_count,
    COUNT(DISTINCT ri.food_id) AS matched_ingredients
FROM recipe r
JOIN recipe_ingredient ri ON r.id = ri.recipe_id
WHERE ri.food_id IN (SELECT food_id FROM resolved_ingredients)
  AND ri.is_main = 1
  AND r.is_archived = 0  -- ★v0.3追加
GROUP BY r.id
ORDER BY matched_ingredients DESC, r.is_favorite DESC, r.reuse_count DESC, r.updated_at DESC
LIMIT 3;
```

### 4.5 レシピ再利用候補検索（v0.3 更新: is_archived 除外）

```sql
WITH ingredient_set AS (
    SELECT value AS food_id FROM json_each(?)
)
SELECT
    r.id, r.name,
    COUNT(ri.food_id) AS total_resolved_ingredients,
    SUM(CASE WHEN ri.food_id IN (SELECT food_id FROM ingredient_set) THEN 1 ELSE 0 END) AS matched
FROM recipe r
JOIN recipe_ingredient ri ON r.id = ri.recipe_id
WHERE ri.food_id IS NOT NULL
  AND r.is_archived = 0  -- ★v0.3追加
GROUP BY r.id
HAVING matched >= (SELECT COUNT(*) FROM ingredient_set) * 0.7
ORDER BY matched DESC, r.reuse_count DESC
LIMIT 5;
```

### 9.4 meal_plan の status 管理（v0.3 新規 / DM-07）

`meal_plan.status` は手動更新を原則とし、以下の補助関数を提供する。

#### 9.4.1 完了判定: `is_meal_plan_completable(plan_id)`

```python
def is_meal_plan_completable(plan_id: int) -> dict:
    """
    meal_plan が「完了化可能」かを判定する。
    全 meal が cooked または skipped で、planned が残っていなければ True。
    """
    meals = fetch_meals_by_plan(plan_id)
    if not meals:
        return {"completable": False, "reason": "no_meals"}

    counts = {"planned": 0, "cooked": 0, "skipped": 0}
    for m in meals:
        counts[m.status] += 1

    if counts["planned"] == 0:
        return {
            "completable": True,
            "cooked": counts["cooked"],
            "skipped": counts["skipped"],
        }
    else:
        return {
            "completable": False,
            "reason": "has_planned_meals",
            "remaining_planned": counts["planned"],
        }
```

対応SQL:
```sql
SELECT
    SUM(CASE WHEN status = 'planned' THEN 1 ELSE 0 END) AS planned_count,
    SUM(CASE WHEN status = 'cooked' THEN 1 ELSE 0 END) AS cooked_count,
    SUM(CASE WHEN status = 'skipped' THEN 1 ELSE 0 END) AS skipped_count
FROM meal
WHERE meal_plan_id = ?;
```

#### 9.4.2 完了化: `complete_meal_plan(plan_id, force=False)`

```python
def complete_meal_plan(plan_id: int, force: bool = False) -> None:
    """
    meal_plan の status を completed に更新する。
    planned が残っている場合は ValueError（force=True なら無視して完了）。
    """
    check = is_meal_plan_completable(plan_id)
    if not check["completable"] and not force:
        raise ValueError(f"Cannot complete plan: {check['reason']}")

    with db.transaction():
        execute("UPDATE meal_plan SET status = 'completed' WHERE id = ?", (plan_id,))
```

#### 9.4.3 キャンセル: `cancel_meal_plan(plan_id, reason=None)`

```python
def cancel_meal_plan(plan_id: int, reason: str = None) -> None:
    """meal_plan をキャンセル状態に。残った planned meal は変更しない（履歴保全）。"""
    with db.transaction():
        execute(
            "UPDATE meal_plan SET status = 'cancelled', notes = COALESCE(notes, '') || ? WHERE id = ?",
            (f"\nCancelled: {reason}" if reason else "", plan_id)
        )
```

#### 9.4.4 UI上の動線（推奨）
- meal_plan 詳細画面に「全て完了とする」ボタン → `complete_meal_plan(force=False)` を呼ぶ
- planned が残っていればワーニング表示し、`force=True` の確認ダイアログ
- 「中止」ボタン → `cancel_meal_plan(reason=ユーザー入力)`

## 10. マイグレーション方針

- v0.2 → v0.3 マイグレーション例:
  1. `ALTER TABLE food_master DROP COLUMN nutrition_json;` (SQLite 3.35+)
  2. `ALTER TABLE recipe RENAME COLUMN instructions TO instructions_md;`
  3. `ALTER TABLE recipe ADD COLUMN is_archived INTEGER NOT NULL DEFAULT 0 CHECK(is_archived IN (0, 1));`
  4. インデックス作り直し（is_archived 関連の部分インデックス）
  5. `PRAGMA user_version = 3;`

- 補助関数は SQLite 側ではなくアプリケーション層に実装
- Alembic で管理する場合、`alembic revision -m "v0.3_changes"` で雛形作成
