### 各層の責務（MVP確定）

| 層 | 配置 | 責務 |
|----|------|------|
| プレゼンテーション | スマホ / PCブラウザ（LAN内） | UI、手動入力、状態管理、期限切迫色分け表示 |
| アプリケーション | 自宅PC（Docker常時稼働） | API、エージェントオーケストレーション、ビジネスロジック |
| データ（本体） | PCローカルSSD | SQLite（在庫・献立・**レシピDB**）|
| データ（保全） | NAS | 日次バックアップ、画像ファイル保存 |
| 外部API | インターネット | LLM（Sonnet/Haiku使い分け）のみ |

> **v0.3変更点**: 楽天レシピAPI接続を外部依存から除外。レシピは LLM 生成＋DB蓄積で完結する構成に。Phase 2 で楽天等の外部API連携を再検討。

## 3. 主要データフロー

### 3.1 在庫登録フロー（手動入力）

```mermaid
sequenceDiagram
    actor User as ユーザー
    participant PWA
    participant API as FastAPI
    participant Agent as 在庫管理Agent
    participant DB as SQLite

    User->>PWA: 食材名・数量・期限を手動入力
    PWA->>API: POST /inventory (JSON)
    API->>Agent: 在庫登録依頼
    Agent->>DB: INSERT stock_item
    DB-->>Agent: OK
    Agent-->>API: 登録結果
    API-->>PWA: 200 OK
    PWA-->>User: 登録完了表示
```

### 3.2 1週間献立提案フロー

```mermaid
sequenceDiagram
    actor User as ユーザー
    participant PWA
    participant API as FastAPI
    participant Router as インテントルーター(Haiku)
    participant Meal as 献立提案Agent
    participant Recipe as レシピ生成Agent
    participant DB as SQLite
    participant Sonnet as Claude Sonnet

    User->>PWA: 「来週の献立を提案して」
    PWA->>API: POST /meal-plan
    API->>Router: ルーティング
    Router->>Meal: 献立提案へ
    Meal->>DB: 在庫照会
    DB-->>Meal: 在庫リスト
    Meal->>DB: 家族プロファイル・過去履歴取得
    DB-->>Meal: 嗜好・アレルゲン・履歴

    Meal->>Sonnet: 1週間献立構成依頼
    Sonnet-->>Meal: 献立案（食材レベル）

    loop 各献立
        Meal->>Recipe: レシピ取得依頼(食材構成)
        Recipe->>DB: 既存レシピDB検索
        alt 該当レシピあり
            DB-->>Recipe: 既存レシピ
        else 該当なし
            Recipe->>Sonnet: レシピ生成
            Sonnet-->>Recipe: レシピ詳細
            Recipe->>DB: INSERT recipe
        end
        Recipe-->>Meal: レシピ詳細
    end

    Meal->>DB: 献立案・買い物リスト保存
    Meal-->>API: 献立 + 買い物リスト
    API-->>PWA: 200 OK
    PWA-->>User: 献立カレンダー + 買い物リスト表示
```

### 3.3 食材指定レシピ提案フロー（v0.3新規 / F-MEAL-11）

```mermaid
sequenceDiagram
    actor User as ユーザー
    participant PWA
    participant API as FastAPI
    participant Recipe as レシピ生成Agent
    participant DB as SQLite
    participant Sonnet as Claude Sonnet

    Note over User,PWA: ケースA: ユーザー手動選択
    User->>PWA: 在庫一覧から食材を複数選択<br/>(例: 鶏もも肉 + 玉ねぎ)
    PWA->>API: POST /recipes/suggest<br/>{ingredients: [...]}

    Note over User,PWA: ケースB: 期限切迫品から自動候補
    User->>PWA: 「期限切迫品でレシピ提案」
    PWA->>API: GET /recipes/suggest-by-expiry

    API->>Recipe: レシピ提案依頼
    Recipe->>DB: 既存レシピDB検索<br/>(指定食材含む)
    DB-->>Recipe: 候補レシピリスト

    alt 既存レシピが3件以上ヒット
        Recipe->>Recipe: 評価・最新性でソート
    else 不足分を生成
        Recipe->>Sonnet: レシピ生成依頼<br/>(食材+家族プロファイル)
        Sonnet-->>Recipe: 1〜3案
        Recipe->>DB: INSERT recipes (新規分)
    end

    Recipe-->>API: レシピ1〜3案
    API-->>PWA: 200 OK
    PWA-->>User: レシピ提案表示<br/>(調理時間・コスト・材料含む)
```

### 3.4 消費（調理完了）フロー

```mermaid
sequenceDiagram
    actor User as ユーザー
    participant PWA
    participant API as FastAPI
    participant Agent as 在庫管理Agent
    participant DB as SQLite

    User->>PWA: 「カレー作った」調理完了ボタン
    PWA->>API: POST /meals/{id}/consume
    API->>Agent: 消費反映
    Agent->>DB: レシピ食材取得
    DB-->>Agent: 食材リスト
    Agent->>DB: 在庫減算 (transaction)
    DB-->>Agent: OK
    Agent-->>API: 消費後の在庫
    API-->>PWA: 200 OK
    PWA-->>User: 残量表示・期限切迫の色分け
```

```mermaid

        int list_id FK
        int food_id FK

        string unit

    }
```

</data_model>

> **v0.3でのデータモデル更新**:
> - `RECIPE` テーブルを独立した第一級エンティティに昇格（蓄積・再利用のため）
> - `MEAL_INGREDIENT` → `RECIPE_INGREDIENT` にリネーム（材料はレシピに紐づく）
> - `RECIPE_RATING` を追加（献立評価と区別、レシピそのものの評価）
> - `RECIPE.is_favorite`, `reuse_count`, `source`, `external_id` を追加
> - `RECIPE_INGREDIENT.is_main` を追加（食材指定レシピ提案のマッチング用）

## 7. 変更履歴

### v0.2 → v0.3
| 領域 | 変更内容 |
|------|---------|
| 外部API | **楽天レシピAPIを削除**（Phase 2で再検討）|
| エージェント | レシピ取得エージェント → **レシピ生成エージェント**にリネーム＆責務変更 |
| 新フロー | **食材指定レシピ提案フロー（F-MEAL-11）を追加** |
| データモデル | RECIPE を独立エンティティに昇格、`is_favorite`/`reuse_count`/`source` 等を追加、RECIPE_RATING 新設 |
| 構成 | 外部接続を Claude API のみに集約 |

### v0.1 → v0.2
| 領域 | 変更内容 |
|------|---------|
| 外部API | Vision API 削除、楽天レシピAPI追加 |
| LLM | Sonnet/Haiku の使い分けを明示 |
| データ層 | SQLite本体をPCローカルSSDに配置、NASはバックアップ・画像のみ |
| エージェント | 通知エージェント削除、レシピ取得エージェント追加 |
| ネットワーク | 外部公開・VPN記述を削除、LAN内限定に簡素化 |
| データモデル | FAMILY_MEMBER → FAMILY_PROFILE に簡素化、離乳食関連属性削除 |
